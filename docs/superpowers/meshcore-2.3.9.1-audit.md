## Part 2: public-API audit (2.3.7 -> 2.3.9.1)

### 2.1 New / changed public surface

VERIFIED by diffing the two installed sources.

New EventTypes (`events.py`):

- `CHANNEL_DATA_RECV = "channel_data"` (2.3.9.1 `events.py:17`; absent in 2.3.7).
- `CLI_REPLY = "cli_reply"` (2.3.9.1 `events.py:28`; absent in 2.3.7).

New packet types parsed (`reader.py` + `packets.py`):

- `PacketType.CHANNEL_DATA_RECV = 27` (`packets.py:123`), parsed at `reader.py:350-382`. Group-channel binary data (`PAYLOAD_TYPE_GRP_DATA`, companion firmware v1.15.0+). Yields `SNR`, `channel_idx`, `path_hash_mode`, `path_len`, `data_type` (16-bit LE), `data_len`, `payload` (hex).
- `PacketType.CLI_REPLY = 29` (`packets.py:125`), parsed at `reader.py:1055-1058`. Dispatches `EventType.CLI_REPLY` with the CLI reply payload.

New `CommandType` members (`packets.py`):

- `SEND_RAW_PACKET = 65` (`packets.py:91`).
- `RUN_CLI_COMMAND = 66` (`packets.py:92`).

New public command-handler methods:

- `commands/device.py:23 run_cli_command(self, cmd: str) -> Event` (opcode `RUN_CLI_COMMAND=66`, waits `CLI_REPLY`/`ERROR`). Runs a CLI command on the LOCAL connected device firmware.
- `commands/device.py:29 send_raw_packet(self, data, priority=0)` (opcode `SEND_RAW_PACKET=65`, waits `OK`/`ERROR`). Accepts bytes or a hex string; prepends a priority byte. Injects a fully-formed raw mesh packet.
- `commands/messaging.py:381 reset_flood_scope(self)` (convenience wrapper: `set_flood_scope(b"")`).
- `commands/messaging.py:384 force_unscoped(self)` (convenience wrapper: `set_flood_scope(b"", force_unscoped=True)`).
- `commands/messaging.py:415 reset_default_flood_scope(self)` (convenience wrapper: `set_default_flood_scope(None)`).

Changed signature (backward compatible):

- `commands/messaging.py set_flood_scope`: 2.3.7 `set_flood_scope(self, scope)` -> 2.3.9.1 `set_flood_scope(self, scope, force_unscoped=False)`. New trailing optional keyword only. RTFM calls it positionally with a single argument (`app/services/flood_scope.py:43` `set_flood_scope(normalized_scope)`, `:54` `set_flood_scope("")`), so existing calls are unaffected. `test_flood_scope_service.py` passed on 2.3.9.1.

Unchanged (VERIFIED identical between versions):

- `self_info` parsed fields (`reader.py`): `adv_type, tx_power, max_tx_power, public_key, adv_lat, adv_lon, multi_acks, adv_loc_policy, telemetry_mode_env/loc/base, manual_add_contacts, radio_freq, radio_bw, radio_sf, radio_cr, name`. No new self-info fields.
- `device_info` parsed fields (`reader.py`): `fw ver, max_contacts, max_channels, ble_pin, fw_build, model, ver, repeat, path_hash_mode`. No new device-info fields.
- `custom_vars` parse (comma/colon `key:value` pairs) is unchanged.
- Top-level `MeshCore` class public methods (`meshcore.py`) are identical (same methods, same line numbers). No new top-level API.
- `__init__.__all__` is identical: `BinaryReqType, BLEConnection, ConnectionManager, EventType, MeshCore, SerialConnection, TCPConnection, logger`.

### 2.2 Relevance recommendations for RTFM

- `run_cli_command` (local-device CLI): USE INTERNALLY / possible UI. RTFM currently drives remote repeater/room CLI over the login channel (`send_cmd`, `routers/server_control.py`). This new call targets the LOCAL companion firmware's own CLI. It could back an advanced "local device console" debug surface, but is not required for existing flows. Medium value.
- `send_raw_packet` (raw packet injection): USE INTERNALLY (advanced/debug only). Lets the backend inject a fully-formed raw mesh packet with a priority byte. Useful for a diagnostics/replay tool; risky to expose in the normal UI. Low-to-medium value, debug-scoped.
- `EventType.CHANNEL_DATA_RECV` + `PacketType.CHANNEL_DATA_RECV` (group-channel binary data): SURFACE ONLY IF NEEDED. This carries binary group-channel payloads (companion v1.15.0+) distinct from text channel messages. RTFM does not subscribe to it today. Relevant only if RTFM wants to ingest non-text channel data (for example structured/telemetry-over-channel). Otherwise irrelevant for now. Low value today.
- `EventType.CLI_REPLY`: consequence of `run_cli_command`. Only relevant if that method is adopted.
- `reset_flood_scope` / `force_unscoped` / `reset_default_flood_scope`: MINOR. Convenience wrappers over the existing `set_flood_scope` / `set_default_flood_scope` that RTFM already calls. RTFM already resets via `set_flood_scope("")` (`app/services/flood_scope.py:54`), so adopting `reset_flood_scope()` would be cosmetic. `force_unscoped` is the only genuinely new behavior (force a message unscoped), potentially useful if RTFM ever needs to bypass a configured flood scope. Low value.

Nothing else meaningful is new. The connection transports (`ble_cx`, `serial_cx`, `tcp_cx`), the parser, telemetry, contacts, binary-request, and stats surfaces are unchanged in their public shapes.

### 2.3 Coordination-critical signatures (for the sibling CAD/GPS feature)

VERIFIED by reading both on-disk sources. All five are UNCHANGED from 2.3.7 to 2.3.9.1.

| Method | 2.3.9.1 signature | Location | Changed vs 2.3.7? |
| --- | --- | --- | --- |
| base raw `send` | `async def send(self, data: bytes, expected_events: Optional[Union[EventType, List[EventType]]] = None, timeout: Optional[float] = None) -> Event` | `commands/base.py:213` | No |
| `set_tuning` | `async def set_tuning(self, rx_dly: int, af: int) -> Event` (opcode `\x15`, rx_dly 4B LE + af 4B LE + 2 zero bytes) | `commands/device.py:98` | No |
| `get_tuning` | `async def get_tuning(self) -> Event` (opcode `\x2b`, waits `TUNING_PARAMS`/`ERROR`) | `commands/device.py:322` | No |
| `get_custom_vars` | `async def get_custom_vars(self) -> Event` (opcode `\x28`, waits `CUSTOM_VARS`/`ERROR`) | `commands/device.py:208` | No |
| `set_custom_var` | `async def set_custom_var(self, key, value) -> Event` (opcode `\x29` + `key:value` utf-8, waits `OK`/`ERROR`) | `commands/device.py:213` | No |

Notes for the sibling:

- The custom-var get/set pair is `get_custom_vars` / `set_custom_var(key, value)`. `get_custom_vars` returns an Event whose payload is a dict of `key -> value` strings parsed from the device's comma-separated `key:value` list (`reader.py` CUSTOM_VARS block, unchanged). `set_custom_var` takes a single `key` and single `value`, both str (they are utf-8 encoded and joined with `:`).
- The base `send(...)` low-level API is byte-for-byte identical, including the docstring guidance that callers must check `result.is_error()` when `EventType.ERROR` is in `expected_events`.
- `set_tuning` / `get_tuning` opcodes and wire format are identical.

The bump is safe for the CAD/GPS feature's reliance on these five methods.
